# Лаборатори №1 — UI автомат тест (Playwright)

Нэр - Б.Азтүшиг
Код - B232270014

## Зорилго

Энэхүү лабораторийн ажлаар Playwright ашиглан SauceDemo веб сайтын хэрэглэгчийн интерфэйсийн үндсэн үйлдлүүдийг автомат тестээр шалгав.

## Ашигласан технологи

- Node.js 18+
- TypeScript
- Playwright Test
- Chromium
- Туршилтын сайт: <https://www.saucedemo.com>

## Хийгдсэн тестүүд

1. **Амжилттай нэвтрэх** — `standard_user` хэрэглэгчээр нэвтэрч Products хуудас нээгдсэнийг шалгана.
2. **Амжилтгүй нэвтрэх** — буруу нууц үг оруулахад алдааны мэдэгдэл гарсныг шалгана.
3. **Бараа сагслах** — нэвтэрсний дараа Sauce Labs Backpack барааг сагсанд нэмсэн эсэхийг шалгана.

Тестүүд `getByRole`, `getByPlaceholder`, `getByText`, `getByTestId` зэрэг locator болон `expect` assertion ашигладаг. Тест бүр тусдаа хуудас/контекстээр ажилладаг. Амжилттай нэвтэрсэн тестүүдийн дараа `afterEach` hook Logout үйлдэл хийнэ; буруу нэвтрэлтийн тестэд нэвтрэх session үүсдэггүй тул Logout хийх боломжгүй.

## Playwright ба Selenium-ийн харьцуулалт

Playwright нь элемент бэлэн болохыг auto-wait механизмаар хүлээдэг тул олон тохиолдолд гараар wait бичих шаардлага багасдаг. Selenium-д зарим нөхцөлд explicit wait-ийг өөрөө тодорхойлох хэрэгтэй. Playwright нь браузерын хэрэгслүүдийг нэг командаар суулгах боломжтой. Selenium-д ашиглаж буй браузерт тохирох driver-ийн тохиргоо шаардлагатай байж болно. Playwright-ийн Codegen нь браузер дээрх үйлдлээс тестийн код үүсгэж өгдөг. Trace Viewer нь тестийн алхам болон DOM snapshot-ийг харахад тусалдаг. Selenium нь Java, Python, C#, JavaScript зэрэг олон хэлтэй өргөн экосистемтэй бол Playwright нь JavaScript/TypeScript, Python, Java, C# хэлийг дэмждэг. Аль хэрэгслийг сонгох нь төслийн хэл, орчин болон тестийн хэрэгцээнээс хамаарна.

## Trace Viewer туршилт

Энэ туршилтаар Playwright тестийн алдааг хэрхэн илрүүлж, шалгаж болохыг судалсан. Үүний тулд SauceDemo вебсайт руу нэвтрэх үйлдэл хийсний дараа зориудаар буруу assertion бичиж тестийг унагаасан.

Тестийг ажиллуулахад This is an intentional error гэсэн текст дэлгэц дээр байхгүй тул assertion амжилтгүй болж, тест FAIL болсон. Playwright нь энэ тестийн ажиллагааны мэдээллийг trace.zip файлд хадгалсан.

Trace Viewer-ийг ашиглан дараах зүйлсийг ажигласан:

Actions: Browser дээр хийгдсэн үйлдлүүдийг дарааллаар нь харуулж байсан. Login хуудас руу орох, username болон password оруулах, Login товч дарах зэрэг алхмуудыг шалгах боломжтой.

Source: Тестийн код болон тухайн үйлдэлтэй холбоотой кодын мөрийг харах боломжтой.

Errors: Зориуд буруу бичсэн assertion-ийн алдааны мэдээлэл харагдаж байсан.

Snapshots: Үйлдэл хийгдэх үеийн хуудасны төлөвийг шалгах боломжтой.

Энэ туршилтаас Trace Viewer нь тест яагаад амжилтгүй болсныг зөвхөн алдааны мессежээр бус, өмнөх үйлдлүүд болон тухайн үеийн хуудасны төлөвтэй хамт шалгахад хэрэгтэйг ойлгосон.

Trace файл: evidence/trace-intentional-failure.zip

## Playwright Codegen туршилт

Codegen ашиглан SauceDemo вебсайт дээр login хийх болон бүтээгдэхүүнийг сагсанд нэмэх үйлдлүүдийг туршсан.

Browser дээр хийсэн үйлдлүүдийн дагуу Playwright тестийн код автоматаар үүсэж байгааг ажигласан. Үүссэн кодоос getByRole(), getByPlaceholder() зэрэг locator ашиглан элементүүдийг тодорхойлж байгааг харсан.

Codegen нь тестийн эхний хувилбарыг хурдан үүсгэхэд тусалдаг боловч автоматаар үүссэн кодыг шууд ашиглахын оронд шалгаж, шаардлагагүй үйлдлүүдийг цэвэрлэх хэрэгтэй гэж дүгнэсэн.

## Туршилтын дүгнэлт

Эдгээр туршилтаар Playwright нь тест бичихээс гадна тестийн ажиллагааг хянах, алдааны шалтгааныг судлах боломжтойг ойлгосон. Codegen нь тестийн код үүсгэхэд, Trace Viewer нь тестийн алдааг алхам бүрээр шинжлэхэд тусалдаг гэж дүгнэлтээ гаргалаа.
